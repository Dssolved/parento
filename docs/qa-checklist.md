# QA checklist для Parento

Этот чеклист нужен после наполнения Supabase демо-контентом из `supabase/demo-content.sql`.

## Подготовка

- Запустить локально: `npm run dev`.
- Открыть `http://localhost:5173/`.
- Убедиться, что Supabase env-переменные заполнены.
- Выполнить `supabase/demo-content.sql` в Supabase SQL Editor.
- **Выполнить остальные миграции** — порядок и проверка «что уже накатано» в
  [supabase-migrations.md](./supabase-migrations.md). Без них не работают: персонализация по
  неделям, форма email на лендинге, аналитика, пробный Premium.
- Для чистого теста создать нового пользователя или выйти из текущего аккаунта.

## Новый Free-пользователь

- Зарегистрироваться новым email.
- Подтвердить email, если подтверждение включено.
- Войти в аккаунт.
- Пройти onboarding:
  - выбрать этап;
  - для этапов «Ждём малыша» / «Малыш до года» — увидеть шаг с датой, проверить календарь
    (переключение месяцев и годов, недоступные даты вне диапазона);
  - проверить кнопку «Уточню позже» — шаг должен пропускаться без ошибки;
  - выбрать роль;
  - увидеть финальный экран со стартовым курсом.
- Нажать `Перейти к первому уроку`.
- Открыть урок и отметить его как пройденный.
- Нажать `Следующий урок`.
- Вернуться в `Моё обучение`.
- Проверить:
  - число пройденных уроков увеличилось;
  - блок продолжения ведёт к следующему уроку;
  - профиль показывает выбранный этап и роль.
- В отдельном тестовом аккаунте проверить удаление аккаунта из профиля:
  - кнопка активируется только после ввода `УДАЛИТЬ`;
  - после удаления происходит выход на главную;
  - пользователь исчезает из Authentication;
  - профиль и прогресс удалены из таблиц.
- Проверить обратную связь:
  - открыть `/feedback`;
  - отправить отзыв с оценкой и контактом;
  - убедиться, что запись появилась в таблице `feedback`;
  - проверить ссылку из footer;
  - проверить карточку обратной связи в профиле;
  - после 3 пройденных уроков проверить блок на дашборде и кнопку `Не сейчас`.

## Free-пользователь и Premium-доступ

- Открыть каталог.
- Найти Premium-курс.
- Открыть страницу Premium-курса.
- Проверить:
  - виден баннер `Premium доступ`;
  - кнопка ведёт на страницу подписки;
  - уроки курса заблокированы.
- Открыть Free-курс со смешанным доступом:
  - `Старт перед беременностью`;
  - `Беременность спокойно по триместрам`;
  - `Первый месяц с малышом`.
- Проверить, что первые уроки доступны, а третий урок помечен Premium и ведёт на подписку.

## Персонализация по неделям

Ключевая фича, проверять на всех трёх сценариях.

- **Этап `pregnancy` с заполненной ПДР:**
  - в каталоге сверху есть секция «Актуально для вас сейчас» с плашкой номера недели;
  - в ней только курсы, чей диапазон реально включает текущую неделю (курсы других триместров
    показываться не должны);
  - на дашборде есть блок «Актуально на вашей неделе»;
  - в профиле видно текущую неделю рядом с датой.
- **Этап `newborn` без даты:**
  - вместо секции показывается мягкая подсказка «Укажите дату…» со ссылкой в профиль;
  - после указания даты в профиле секция появляется.
- **Этап `planning`:**
  - ни секции, ни подсказки нет вообще (недели неприменимы).
- Проверить плашку диапазона недель на карточках курсов во всём каталоге, а не только в секции.

## Фильтр и сортировка каталога по неделям

- Выбрать этап «Беременность» или «До года» — под фильтрами появляется блок «Неделя».
- Проверить режимы:
  - «Все недели» — фильтр не применяется;
  - «Актуально для меня» — активен только если этап совпадает с этапом профиля и дата указана,
    иначе кнопка заблокирована с подсказкой;
  - «Выбрать неделю» — слайдер меняет выдачу вживую.
- Переключить этап на «Все» или «Планирование» — блок «Неделя» исчезает, фильтр сбрасывается.
- Проверить сортировку «По неделе»: курсы без диапазона уходят в конец.

## Лендинг

- Проверить хиро: эйброу, тег-лайн «Ваш путь родителя», вопрос-ответ в подзаголовке.
- Демо-виджет «Попробуйте прямо сейчас»:
  - переключение табов «Беременность» / «Малыш до года» сбрасывает неделю;
  - слайдер подсвечивает подходящие карточки и гасит остальные;
  - счётчик «актуально курсов: N из 4» меняется вместе со слайдером.
- Форма сбора email:
  - отправить адрес, увидеть «Спасибо! Вы в списке»;
  - проверить, что запись появилась в таблице `waitlist_signups`;
  - отправить тот же адрес повторно — не должно быть ошибки для пользователя.
- Проверить иконку и заголовок вкладки браузера.

## Premium-пользователь и пробный доступ

- Перейти на страницу `Подписка`.
- Нажать `Попробовать Premium 7 дней бесплатно`.
- Проверить:
  - статус стал `Premium`;
  - рядом появился бейдж с числом оставшихся дней и прогресс-бар;
  - склонение корректное (1 день / 2 дня / 5 дней);
  - кнопка активации заблокирована, пока Premium активен.
- Открыть Premium-курс. Проверить:
  - баннер блокировки исчез;
  - уроки открываются;
  - уроки можно отмечать пройденными;
  - дашборд предлагает продолжить обучение.
- **Проверить автооткат.** Быстрый способ — вручную сдвинуть срок в базе и перезагрузить страницу:
  ```sql
  update profiles set premium_expires_at = now() - interval '1 day' where email = 'ваш@email';
  ```
  После перезагрузки подписка должна сама стать `free`, а Premium-контент — снова закрыться.

## Прогресс

- Пройти 2-3 урока в одном курсе.
- Открыть страницу курса.
- Проверить:
  - процент курса изменился;
  - отображается `N из M уроков`;
  - пройденные уроки имеют бейдж `Пройдено`.
- Пройти последний урок курса.
- Открыть дашборд.
- Проверить состояние завершённого курса.

## Админка

- Войти под admin-профилем.
- Открыть `/admin`.
- Создать новый курс.
- Добавить 2 урока.
- Проверить публикацию:
  - новый курс и новый урок по умолчанию создаются как черновики;
  - черновик курса не виден в каталоге;
  - черновик урока не виден на странице опубликованного курса;
  - опубликованный урок внутри черновика курса не открывается по прямой ссылке.
- Проверить Markdown:
  - заголовок;
  - список;
  - таблицу;
  - режим предпросмотра.
- Добавить URL обложки.
- Отметить урок как Premium.
- Проверить в пользовательском режиме, что доступ к уроку закрыт для Free.
- Отредактировать урок.
- Удалить тестовый урок.

## Визуальная проверка

- Проверить страницы на desktop:
  - главная;
  - onboarding;
  - дашборд;
  - каталог;
  - курс;
  - урок;
  - подписка;
  - профиль;
  - админка.
- Проверить основные страницы на мобильной ширине.
- Особое внимание:
  - кнопки не переносят текст некрасиво;
  - карточки курсов не прыгают из-за картинок;
  - footer не перекрывает контент;
  - длинные названия уроков не ломают сетку.

## Мобильная версия

- Проверить, что мобильный viewport действительно применяет мобильную верстку после:
  - обычного открытия страницы;
  - refresh;
  - перехода между страницами;
  - открытия DevTools/device mode;
  - возврата с desktop-ширины на mobile-ширину.
- Зафиксировать страницы, где вместо мобильной верстки остаётся desktop-раскладка.
- Проверить хэдер на мобильной ширине:
  - текущая навигация выглядит перегруженной;
  - нужен burger-menu для ссылок `Моё обучение`, `Курсы`, `Подписка`, `Профиль`, `Админ`;
  - в открытом меню должны быть понятные состояния активной страницы и кнопка выхода.
- Проверить, что хэдер не переносит элементы некрасиво и не занимает слишком много высоты.

## Аналитика

Проверяется через консоль браузера (F12) и через SQL.

- Выполнить действия: завершить онбординг, отметить урок пройденным, кликнуть карточку в
  «Актуально сейчас», нажать любую Premium-кнопку.
- Убедиться, что в таблице появились записи:
  ```sql
  select event_name, properties, created_at from events order by created_at desc limit 20;
  ```
- Ожидаемые события: `onboarding_completed`, `lesson_completed`, `recommended_course_clicked`,
  `premium_cta_clicked` (с разными `source`).
- Проверить, что вьюхи отдают данные: `select * from v_recommended_course_clicks;`
- В консоли не должно быть сообщения «Проверьте, что выполнена миграция supabase/add-events.sql» —
  если оно есть, миграция не накатана.
- Pageviews смотрятся в панели Vercel (Analytics). Custom Events там **не появятся** — они на Pro,
  все продуктовые события живут в Supabase.

## Локализация и числительные

- Профиль: при 1 пройденном уроке должно быть «1 урок», при 2 — «2 урока», при 5 — «5 уроков».
- Страница курса и дашборд: «N из M уроков» с правильной формой слова.
- Страница подписки: «N дней» с правильной формой.

## После проверки

- Выписать найденные UX-проблемы отдельным списком.
- Разделить их на:
  - критично для пути пользователя;
  - визуально неприятно;
  - можно отложить.
