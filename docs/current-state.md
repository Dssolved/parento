## 1. Что это за проект в двух абзацах

Parento — русскоязычная freemium веб-платформа для будущих и молодых родителей: курсы и уроки,
выстроенные в маршрут от планирования беременности до первого года ребёнка. Стек: React 19 + Vite +
TypeScript + TailwindCSS 3 + TanStack Query v5 + Supabase (auth/БД) + Vercel (хостинг).

Ключевая отличительная фича, вокруг которой строится позиционирование, — **адаптивная персонализация
по неделям**: пользователь указывает ПДР (предполагаемую дату родов) или дату рождения малыша,
платформа считает текущую «неделю» и показывает курсы, актуальные именно для этого срока.
Формула позиционирования из бизнес-плана: *трекер говорит, ЧТО происходит; Parento говорит, ЧТО ДЕЛАТЬ.*

Подробный продуктовый контекст — в [project-overview.md](./project-overview.md).
Техническая карта — в [architecture.md](./architecture.md).

### 3.1. SQL-миграции

Статус применения к боевой базе Supabase **точно не подтверждён** по части файлов — проверьте
одним запросом в Supabase SQL Editor:

```sql
select
  to_regclass('public.events')              as events_table,
  to_regclass('public.waitlist_signups')    as waitlist_table,
  to_regclass('public.v_activation_funnel') as analytics_views,
  (select count(*) from information_schema.columns
     where table_name = 'profiles' and column_name = 'premium_expires_at') as premium_trial_col,
  (select count(*) from information_schema.columns
     where table_name = 'courses' and column_name = 'week_from')           as adaptive_weeks_col,
  (select count(*) from courses where week_from is not null)               as courses_with_weeks;
```

## 4. Известные проблемы и риски

### 4.1. 🔴 RLS включена не на всех таблицах — платный контент технически открыт

В `supabase/schema.sql` RLS включена **только** для `feedback`. Таблицы `profiles`, `courses`,
`lessons`, `progress` живут без RLS. Новые таблицы (`waitlist_signups`, `events`) RLS имеют,
но только с политикой на вставку.

Что это значит на практике: анонимный ключ Supabase лежит в клиентском бандле, поэтому через
REST API можно:

- прочитать все `profiles` (email, имя, статус подписки);
- прочитать контент **всех** уроков, включая Premium и неопубликованные черновики, минуя пейволл;
- вероятно, изменить собственный `subscription` на `premium` напрямую.

Проверка доступа сейчас целиком клиентская (`PrivateRoute`, `src/lib/access.ts`) — это UX-гейт,
а не граница безопасности. Проблема **не создана в этой сессии**, она унаследована из базовой схемы,
но перед публичным запуском её нужно закрыть RLS-политиками. Отдельная задача.

### 4.2. Предупреждения, не ломающие сборку

- `oxlint`: `react(only-export-components)` в `src/context/AuthContext.tsx:129` — файл экспортирует
  и провайдер, и хук `useAuth`. Идиоматично, но новое правило oxlint 1.74 советует разнести по файлам.
  Не исправлено сознательно.
- Консоль: React Router v6 ругается на будущие флаги `v7_startTransition` и `v7_relativeSplatPath`.
  Уйдёт при миграции на v7.

### 4.3. `schema.sql` не самодостаточен

`supabase/schema.sql` описывает **базовую** схему без изменений из миграций. Для новой БД нужно
выполнить `schema.sql`, а затем все `add-*.sql` по порядку. Файл сознательно не переписывался,
чтобы не расходиться с историей миграций.

### 4.4. Демо-данные и UUID из исходного ТЗ

В исходном ТЗ на персонализацию были указаны UUID курсов, которых в базе не существует (выдуманные).
Реальные демо-курсы используют ID вида `00000000-0000-4000-8000-0000000001XX`. Миграция
`add-adaptive-weeks.sql` переписана под реальные ID. Если где-то всплывут UUID вида
`b8d1072b-...` — это мусор из старого ТЗ, им верить нельзя.

1. **Применить оставшиеся миграции** и пройти ручное тестирование из п. 3.3 — самое blocking.
2. **Закрыть дыру с RLS** (п. 4.1) — обязательно до публичного запуска, тем более до реальных платежей.

   (`v_recommended_course_clicks`), где кликают Premium (`v_premium_cta_clicks`).
4. Обновить `docs/qa-checklist.md` по факту прохождения — там уже добавлены новые сценарии.
5. Мажорные апгрейды зависимостей — по одному, с прогоном сборки и ручной проверкой.
6. Контент: сейчас 11 курсов (6 исходных демо + 5 добавленных под недели). Для реального запуска
   нужен нормальный контент и медвалидация, о которой говорит бизнес-план.

## 7. Как работать с проектом

```bash
npm install
npm run dev      # localhost:5173
npm run lint     # oxlint
npm run build    # tsc -b && vite build
```

Проверки перед коммитом: `npx tsc -b`, `npm run lint`, `npm run build`.

Файл `.claude/launch.json` (конфиг превью-сервера для ассистента, порт 5199) намеренно **не
коммитится** — это локальный хелпер, у пользователя свой дев-сервер на 5173.
